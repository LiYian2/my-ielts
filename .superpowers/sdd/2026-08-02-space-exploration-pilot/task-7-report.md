# Task 7 implementation report

## RED

The initial Task 7 tests were written before either stage component existed, so the focused suite failed at module resolution for `RecallStage.vue` and `ProductionStage.vue`.

Fix round 1 added a `setProps()` regression: an externally saved answer arriving after `ProductionStage` had created its empty local draft did not update the text area or rubric. The root cause was the answers watcher: it merged the external answer into its saved-answer record but hydrated a task draft only when that draft did not already exist.

## GREEN

`ProductionStage` now marks user-edited drafts dirty. Incoming saved answers hydrate unchanged drafts, including text and self-assessment, while dirty drafts retain their local text and rubric. Incoming values always update the saved-answer record, so reference availability remains accurate even during a local conflict. A local save or persisted rubric update clears dirty state, allowing later external progress updates to hydrate normally.

The regression suite also covers late saved answers, a remote answer for a task opened later, dirty-local conflict preservation, per-task draft/rubric/reference isolation, repeated save/check recording, Enter plus repeated recall completion, and Unicode-whitespace multiword recall input.

`components.d.ts` was generated by the configured `unplugin-vue-components` plugin (`dts: true`) during the successful production build. Its added registrations exactly match the Task 5–7 component files: `LessonReader`, `WordCardPanel`, `ProductionStage`, and `RecallStage`.
